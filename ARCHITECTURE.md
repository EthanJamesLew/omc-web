# Architecture

omc-web compiles and simulates Modelica entirely in a web browser. Three
wasm artifacts and one runtime filesystem do the work; everything else
in the repo exists to build, test, and ship them reproducibly.

## The three wasm projects + runtime FS

```
┌────────────────────┐      ┌──────────────────────┐      ┌────────────────────┐
│  omc.wasm          │      │  emception (vendor)  │      │  per-model wasm    │
│  (compiler)        │      │  clang + wasm-ld     │      │  (sim, produced    │
│                    │──C──▶│  built by jprendes   │──.wasm─▶│  in-browser)      │
│  emsdk 3.1.74      │      │                      │      │                    │
└────────────────────┘      └──────────────────────┘      └────────────────────┘
         ▲                            ▲                            ▲
         │                            │                            │
   .mo source                runtime-fs.zip                init.xml + JacA.bin
   from user                 (headers + sysroot)           from omc.wasm output
   + MSL boot/full
```

| Project              | What it is                                       | emsdk    | Lives in                          |
| -------------------- | ------------------------------------------------ | -------- | --------------------------------- |
| **omc-wasm**         | OpenModelica compiler, OMBootstrapping → .wasm   | 3.1.74   | `projects/omc-wasm/`              |
| **sim-runtime**      | Static archives linked into every model wasm     | 3.1.24   | `projects/sim-runtime/`           |
| **emception-bundle** | Vendored jprendes/emception + overlay.js         | none     | `projects/emception-bundle/`      |
| **runtime-fs**       | headers.zip + sysroot.zip staged into emception  | (3.1.24) | `runtime-fs/`                     |
| **msl**              | Curated boot + full-MSL .zips                    | none     | `msl/`                            |

### Why two emsdks

emception bundles LLVM-16 wasm-ld. That linker cannot link `.o`/`.a`
files produced by clang ≥ 17 because they emit `call_indirect_overlong`
and rename `setjmp` (`__wasm_setjmp` vs `saveSetjmp`). So:

- **omc.wasm** is a one-shot native-link step; we use a modern emsdk
  (3.1.74) for it and don't worry about emception consuming its output.
- **sim-runtime** libs are linked **inside the browser by emception**,
  so they must be ABI-compatible with LLVM 16 → emsdk 3.1.24.

Both versions live in `/opt/emsdk/{3.1.24,3.1.74}` inside the Docker
build image. `versions.lock` pins both.

## Build flow

```
                 versions.lock
                       │
              tools/check-versions.sh  ← CI gate
                       │
   ┌───────────────────┼──────────────────────┐
   ▼                   ▼                      ▼
projects/omc-wasm   projects/sim-runtime    msl/
   │ (emsdk 3.1.74)   │ (emsdk 3.1.24)        │
   ▼                   ▼                      ▼
omc.{wasm,js,data}  libs/*.a + omcweb_gc_stub.o  msl-boot.zip + msl-full.zip
                       │
                       ▼
                  runtime-fs/  ← combines headers + sysroot .a's
                       │
                       ▼
                  headers.zip + sysroot.zip
                       │
   ┌───────────────────┴──────────────────────┐
   ▼                                          ▼
projects/emception-bundle (vendor)        common-shims/ (shared C)
   │                                          │
   └─────────────┬────────────────────────────┘
                 ▼
            web/public/ (the static site)
```

`make all` runs each stage in order. The Docker build container
(`docker/Dockerfile`) is the source of truth for the build env.

## Migration from PoC

The original PoC lives under `re-poc/` as a frozen reference, tagged
`v0.1-poc`. Its scripts and shims are NOT consumed by the new tree —
they exist so future maintainers can read the original spelunking and
the new tree can stay tidy. New work happens at the top level.

## Test bench

`tests/models/<Name>/` holds a `model.mo`, per-variable
`tolerances.yaml`, and `refs/<solver>.mat` (binary, committed). The
Node runner (`tests/runners/node/`) is the fast tier; Playwright drives
the real browser for cross-engine drift detection. References are
regenerated by `make regen-references`, which runs native OMC inside
`docker/Dockerfile.native-omc` against the same OpenModelica SHA pinned
in `versions.lock`. `reference-manifest.json` ties each .mat to the SHA
it was generated from; CI fails if the SHA moves without a regen.

## Web app

Vanilla `web/src/{index.html,app.js,style.css}`. `make stage` copies
the three wasm artifacts + runtime-fs + MSL zips into `web/public/`,
emits `integrity.json` with SRI hashes, and produces a 100% static
deploy-anywhere site. No bundler, no framework.
