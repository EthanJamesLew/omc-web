      State of the port
      
This page loads our wasm-compiled OpenModelica compiler and runs it
      on whatever Modelica source you put in the editor. The compiler IS OMC —
      built from OMBootstrapping's pre-generated C of the full compiler (894
      sources, BackEnd + SimCode + CodegenC all present, none of them stubbed).
      What you see in the output panel comes from OMC itself.


      
Currently working:

      
    
        
  • omc.wasm links cleanly with 0 unresolved symbols (19 MB).
    • 
        
  • The wasm runtime initialises, parses argv, opens files from MEMFS.
    • 
        
  • OMC's front-end starts processing your source.
    • 
      


      
Currently failing:

      
    
        
  • Both the .mo path (via loadFile → List.map2)
            and the .mos scripting path (via evaluateToStdOut) hit
            alignment faults inside MetaModelica's record-field reads. SAFE_HEAP
            traps the misalignment but the offending callsite is deep in OMC's
            generated C, not in our shim layer.
    • 
        
  • Probable cause: one of the ~165 auto-generated stubs returns
            data with wrong tag/alignment, or there's a wasm pointer-width
            mismatch in a hand-written runtime function. Debug requires
            building with -g, instrumenting MMC_FETCH, and tracing.
    • 
      


      
Not yet wired (next-layer work):

      
    
        
  • OPENMODELICAHOME directory layout in MEMFS (so MSL imports resolve).
    • 
        
  • wasm-clang for compiling OMC's generated C in-browser.
    • 
        
  • sundials + simulation runtime as a wasm static archive to link the per-model output against.
